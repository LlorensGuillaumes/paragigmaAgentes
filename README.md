# SpeedParadigm · Gestor de tareas

Aplicación web en español para añadir, consultar, completar, reabrir y borrar tareas. Los filtros permiten ver todas las tareas o solo las pendientes o completadas.

## Stack y estructura

- Next.js con App Router, React, TypeScript y Tailwind CSS.
- Supabase Postgres y el cliente oficial `@supabase/supabase-js`.
- `src/app/page.tsx` contiene la interfaz y sus estados de interacción.
- `src/lib/supabase.ts` centraliza las operaciones de la tabla `tasks`, la validación de títulos y los errores de acceso a datos.

## Arranque local

1. Instala las dependencias con `npm ci`.
2. Crea `.env.local` en la raíz y configura la URL del proyecto y su clave pública anon.

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=
   NEXT_PUBLIC_SUPABASE_ANON_KEY=
   ```

3. Verifica que el proyecto de Supabase dispone de `public.tasks` y que sus permisos y políticas permiten las operaciones desde el rol que usa la aplicación.
4. Ejecuta `npm run dev` y abre <http://localhost:3000>.

Las variables `NEXT_PUBLIC_` se incluyen en el código del navegador. Usa únicamente la clave pública anon. Git ignora `.env.local` mediante la regla `.env*`.

## Esquema de referencia para Supabase

Para un proyecto nuevo, una tabla compatible puede crearse así desde el editor SQL de Supabase. Si ya existe `public.tasks`, conserva su esquema. El cliente admite identificadores numéricos o de texto.

```sql
create table public.tasks (
  id bigint generated by default as identity primary key,
  title text not null,
  completed boolean not null default false,
  created_at timestamptz not null default now()
);

alter table public.tasks enable row level security;
```

La aplicación usa el rol `anon` porque no incluye autenticación. Con RLS activado, configura los permisos y políticas de `SELECT`, `INSERT`, `UPDATE` y `DELETE` según el acceso previsto. Las mutaciones devuelven la fila afectada y también requieren permiso de lectura. Permitir operaciones al rol `anon` concede ese acceso a cualquiera que pueda consultar el proyecto con su clave pública.

## Flujo multiagente

- `AGENTS.md` y `CLAUDE.md` definen la coordinación del proyecto y el ciclo de implementación y auditoría.
- `.claude/agents/develop.md` define el rol **develop**, que implementa los cambios y corrige los fallos detectados.
- `.claude/agents/testing.md` define el rol **testing**, que audita la seguridad, el tipado, el tratamiento de errores y el comportamiento de la interfaz, y comprueba la compilación.
- Si la auditoría detecta fallos, **develop** los corrige y **testing** vuelve a verificar hasta emitir su aprobación.

Ejecuta `npm run lint` para revisar el código y `npm run build` para verificar la compilación de producción.
